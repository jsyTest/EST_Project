## 실제 Notion 연결 결과와 미검증 사항

실행 환경의 토큰·승인된 테스트 부모가 준비되지 않아 **실제 API 호출 0회, 실제 생성 객체 0개**다. 공유할 실제 페이지·DB·View ID와 URL은 없다. 회사 Business 요금제를 사용할 수 있다고 해서 해당 계정 접근 권한이 있다고 가정하지 않았다.

실제 계정 연결·페이지/DB 생성·수식 파싱과 계산·재계산·요금제·차트 렌더링·Dashboard 화면은 모두 미검증이다. 화면 확인 상태는 not_performed다.

API 코드에서는 차트·Dashboard 요청이 거절되면 실패 단계를 기록한다. Dashboard 거절 시 독립 보기를 시도하고 partial로 보고한다. 400 오류를 자동으로 'API 미지원'이나 '요금제 문제'로 단정하지 않는다. 표 하단 합계 설정은 제외하며 수동 또는 숫자 KPI 대안이다.

## 보안·실패·중복 처리

- 토큰은 환경변수→API 헤더에만 사용. HTML·브라우저 JS·Git·상태 파일·로그에 기록하지 않음.
- 공식 API origin 고정, redirect 거부, 타임아웃.
- 기존 회사 페이지·DB 수정/삭제와 자동 롤백 없음.
- 쓰기 요청 전 단계 상태를 로컬에 저장. 생성한 ID와 실패 단계 보존.
- 완료/부분 완료 run-id의 재실행은 추가 API 호출 없이 기존 결과 반환.
- 미완료·응답 불확실·손상 상태·잠금은 재생성을 차단.
- 429는 제한적으로 재시도하고 쓰기 5xx·응답 유실은 맹목적으로 재시도하지 않음.
- 여러 컴퓨터 간 중복 방지와 자동 복구는 미구현. 상태 파일 삭제나 run-id 변경으로 실패를 우회하면 중복 생성될 수 있음.

## 사용자에게 필요한 준비

로컬 .env에 NOTION_API_TOKEN과 NOTION_TEST_PARENT_PAGE_ID를 직접 설정하고, 제한된 테스트 페이지 접근·read/insert/update 권한·요금제를 확인해야 한다. 토큰을 채팅에 출력하도록 요구하지 않는다.

그 뒤 README에 따라 Dry Run을 검토하고 다음 형식으로 실제 실행한다.

`node --env-file=.env scripts/notion-poc/cli.mjs apply --run-id nb-v2-002 --confirm-parent <승인한-테스트-페이지-UUID>`
