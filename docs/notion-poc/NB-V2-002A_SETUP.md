# NB-V2-002A 개인 Notion Free 연결 준비

기준일: 2026-10-29. 사용자가 선택한 환경은 **개인 Notion Free의 테스트 전용 페이지**다. 회사 환경은 사용하지 않는다.

현재 상태: **부분 완료 — 사용자 승인 후 실제 핵심 생성·계산·보기 API 검증 통과**. 최초 preflight의 전송 오류와 `404 / object_not_found`는 연결 추가 후 해소됐다. 사용자는 부모 `4081f60f-fdfa-80dd-9435-dfd053c1d4b3` 아래 교육 1개·DB 6개·가상 행 16개·도넛 최대 1개·표 3개 생성과 AT04 변경을 명시적으로 승인했다. 초기 수식 오류는 기존 빈 DB를 보존한 제한적 수정으로 해결했다. 실제 출석률 75%→100%, 수료율 50%, 보기 4개 재조회와 로컬 검사 37개를 통과했다. Dashboard·추가 차트는 Free 계획에서 제외했고 실제 UI는 브라우저 호스트 접근 불가로 미검증이다. [최종 보고서](NB-V2-002A_REPORT.md), [ChatGPT 전달문](NB-V2-002A_CHATGPT_HANDOFF.md).

토큰 값은 출력하지 않았다. preflight는 실행 상태 디렉터리를 만들지 않으며, 이후 승인된 실행 기록은 Git 제외 디렉터리에 저장했다. 지정 부모와 이번 생성물만 조회·수정했다. 아래는 재현을 위한 설정 안내이며 이번 실행의 승인·생성은 이미 완료됐다.

## 1. 테스트 페이지 만들기

개인 Notion에서 내용이 없는 새 페이지를 만들고 `NB-V2-002A 테스트`처럼 구분 가능한 이름을 붙인다. 기존 회사·개인 자료가 있는 페이지를 부모로 지정하지 않는다. 연결은 공유된 부모의 하위 페이지에도 접근할 수 있다.

## 2. 개인 워크스페이스용 연결 준비

[Notion 개발자 포털](https://app.notion.com/developers/connections)에서 Internal connections를 열고 개인 워크스페이스용 연결을 만든다. 이름 예: `EST 개인 테스트`.

콘텐츠 권한은 Read content·Insert content·Update content를 허용한다. 사용자 정보는 No user information으로 둔다. 이번 작업에 사용자 목록·이메일·댓글 권한은 필요하지 않다.

테스트 페이지의 `••• → 연결/Connections → 연결 추가`에서 해당 연결만 추가한다. 포털의 Content access에서 테스트 페이지를 지정하는 방식도 있다. 전체 워크스페이스나 다른 페이지를 추가할 필요는 없다.

설정 화면의 연결 API 토큰은 로컬 .env에만 입력한다. 생성 메뉴나 워크스페이스가 보이지 않으면 회사 공간을 대신 선택하지 말고 현재 화면의 안내를 확인한다.

근거: [내부 연결·페이지 접근](https://developers.notion.com/guides/get-started/internal-connections), [콘텐츠·사용자 권한](https://developers.notion.com/reference/capabilities).

## 3. 로컬 설정 파일 채우기

프로젝트 루트 `.env`에 빈 변수 선언을 준비했다. 기존 .env가 있었다면 덮어쓰지 않는 방식으로 처리한다. 파일은 Git 제외 대상이며 새로 만들 때 권한을 0600으로 설정했다.

다음 두 변수의 등호 오른쪽을 **로컬 편집기에서만** 채운다.

```dotenv
NOTION_API_TOKEN=
NOTION_TEST_PARENT_PAGE_ID=
```

- 첫 값: 개인 테스트 연결 토큰.
- 둘째 값: 직접 만든 테스트 상위 페이지 ID. 페이지 링크의 32자리 영문·숫자 식별자 또는 하이픈 포함 UUID를 사용한다. URL과 `?` 이후 매개변수는 제외한다.

토큰을 채팅에 보내거나 .env를 ChatGPT 프로젝트 자료에 업로드하지 않는다. 페이지 ID를 찾기 어렵다면 비밀 토큰 없이 테스트 페이지 링크만 전달할 수 있다.

## 4. 읽기 전용 연결 확인

설정을 저장하고 Codex에 `개인 Free 설정 완료`라고 알려준다. Codex는 지정한 부모 페이지만 읽어 실제 이름·ID를 확인한다. 이 단계는 생성 승인과 별개이며 쓰기 요청을 하지 않는다.

직접 확인할 경우 프로젝트 루트에서 다음 명령을 사용할 수 있다.

```sh
node --env-file=.env scripts/notion-poc/cli.mjs preflight --view-profile free
```

preflight는 페이지 이름·ID·응답 URL만 골라 보여준다. 토큰과 작성자·계정 정보는 출력하지 않는다. 읽기 성공만으로 삽입·수정 권한이나 Free 요금제가 확인된 것으로 처리하지 않는다. 이 권한들은 Notion 설정과 이후 승인된 실행에서 따로 확인한다.

## 5. 생성 승인 전에 확인할 계획

- 환경: 사용자가 선택한 개인 Free.
- 부모 이름·ID: 읽기 요청으로 설정 일치 확인 완료. 사용자 승인 시 해당 부모에만 생성.
- 신규 교육 페이지: 1개.
- 운영 DB 5개 + KPI 집계 DB 1개.
- 가상 운영 행 15개 + KPI 요약 행 1개.
- KPI는 실제 집계 DB에서 기대값과 비교.
- 차트: 참여자 유형 도넛 1개.
- 표: 신청자·과정별 신청기록·수강 3개.
- 생성한 AT04만 결석에서 출석으로 변경하고 75%→100% 재계산 확인.
- 기존 객체 삭제·수정·자동 롤백 없음.
- 실제 화면 표시와 메인 페이지에서의 접근은 API 재조회와 별도 확인.

공식 안내상 Free는 차트 1개, Dashboard는 Business/Enterprise에서 제공된다. 따라서 free 프로필은 Dashboard와 숫자 차트 4개·나머지 차트 2개를 호출하지 않고 미검증 사유로 남긴다. 이미 개인 공간에서 Free 차트를 사용 중이면 새 차트가 거절될 수 있다. 기존 차트를 지우거나 요금제를 변경하지 않는다.

이는 회사 Business 기능의 검증 성공이 아니다. [차트 제공 범위](https://www.notion.com/help/charts), [Dashboard 제공 범위](https://www.notion.com/help/dashboards).

**새로운 실제 생성은 실제 부모와 계획을 제시하고 명시적으로 승인받은 범위에서 실행한다.** 이번 실행은 사용자 답변 `승인 — 위 테스트 범위로 생성·검증 실행`으로 승인됐다. 환경 선택이나 설정 완료만으로 생성 승인으로 간주한 것이 아니다.

## 6. 이번 준비 단계의 코드 변경과 검사

- preflight.mjs 신규: 명시한 부모 하나의 메타데이터만 조회.
- cli.mjs: preflight와 --view-profile full/free 옵션.
- schema.mjs: Free용 보기 선택, 요청된 표 3종 반영.
- engine.mjs: 초기 DB별 스키마 확인, Free 미실행 기능 기록과 partial 상태, 프로필 지문.
- poc.test.mjs 등: 준비 단계 34개 이후 제한적 스키마 수정 경로 검사 3개를 추가하여 총 37개 통과.
- schema-repair.mjs: 알려진 400 오류만 기존 빈 DB에서 이어가기 전 검증.
- schema.mjs·verify.mjs·모의 API: 실제 API가 수락한 보조 수식·롤업 방식과 검증 반영.
- 기존 V1 HTML·CSS·JS 및 과거 명세·인계문 보존. 커밋·배포 없음.

읽기 연결·생성·실제 계산·차트/표 구성 API 검증은 통과했다. UI·Business Dashboard 검증은 남아 있다. 최종 결과는 위 보고서와 인계문을 기준으로 한다.
