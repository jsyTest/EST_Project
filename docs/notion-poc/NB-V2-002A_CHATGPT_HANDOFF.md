## 오류와 해결

초기 부모 GET 404는 사용자가 연결 추가 후 같은 부모를 다시 읽어 해소했다. 다른 자료 탐색이나 인증 우회는 하지 않았다.

첫 apply의 metrics batch 5에서 선정 고유 인원/수료인원의 관계 filter/map/unique 계열 수식이 `400 validation_error / Type error with formula`로 거절됐다. 해당 두 식의 거절을 확인한 것이며 함수 전반이 미지원이라는 결론은 아니다. 숫자 보조 수식·신청자별 롤업·1/0 플래그 합산으로 바꿔 9개 배치 의존 순서로 적용했다. 실제 API 수락·스키마 재조회·실제 계산 일치까지 확인했다.

원래 생성한 페이지/DB를 보존했다. repair-schema는 알려진 초기 코드 지문·명시적 400·응답 불확실성 없음·6 DB 식별자·실제 빈 데이터·부모/관계 일치를 확인한 경우에만 이어간다. 데이터나 보기가 있거나 알 수 없는 상태면 거부한다. 실패를 우회해 새 run-id로 생성하지 않았고 삭제·롤백도 하지 않았다. 성공 복구 후 로컬 오류 검토 플래그를 해제했으며 UI 미검증과 계획된 생략은 남겨 뒀다.

## 차트·Dashboard·UI 구분

참여자 유형 도넛 1개와 신청자/과정별 신청기록/수강 표 3개의 생성 및 GET 구성 대조는 통과했다. 도넛 그림/레이블·실제 표 화면·메인 클릭 경로는 미검증이다.

공식 안내상 Free는 차트 1개, Dashboard는 Business/Enterprise 기능이므로 숫자 차트 4개와 유입/과정별 차트 2개, Dashboard를 호출하지 않았다. 거절 응답으로 판정한 것이 아니며 회사 Business 검증 완료도 아니다. 근거: [차트](https://www.notion.com/help/charts), [Dashboard](https://www.notion.com/help/dashboards).

브라우저 도구가 `The browser access host is unavailable`을 반환해 실제 Notion UI를 확인하지 못했다. 교육 메인 아래 inline DB 6개의 소유 관계는 API로 확인했지만 최종 한 화면 대시보드 UX는 사용자 확인 대기다. 사용자는 메인→교육 KPI DB의 교육 전체 집계(출석률 100/수료율 50)→신청자 DB 도넛 보기→신청기록·수강 표→출석 AT04 순으로 화면을 확인하면 된다. Dashboard는 없으므로 Dashboard 클릭 위치는 안내할 수 없다.

## 검증·보안·기존 기능 영향

로컬 `node --test scripts/notion-poc/tests/*.test.mjs` 37개 통과/0실패. V1 모듈 256개 조합의 설계·내보내기 일관성도 통과했다. 기존 V1 파일 diff 없음. 실제 브라우저의 V1 전체 입력·결과 동작은 별도로 확인하지 않았으며 기존 누락 로고 참조·일부 localStorage 예외 처리는 이번에 수정하지 않았다.

실제 manifest로 같은 run-id를 재호출하고 API 접근 시 예외를 던지는 client를 사용해 기존 partial 재사용·API 호출 0회를 확인했다. 실패/응답 유실/잠금/알 수 없는 스키마 복구 거부는 모의 테스트로 검증했다. 다중 컴퓨터·대규모 관계는 보장하지 않는다.

토큰은 로컬 .env만 사용, chmod 0600, Git 제외. 토큰·전체 응답·계정 정보는 보고서/로그에 출력하지 않았다. 사용자 목록·워크스페이스 검색·회사 자료에 접근하지 않았다. 기존 부모와 이번 생성물만 읽고 이번 생성물만 수정했다. 공개 공유·권한 확대·삭제·배포 없음. 실제 요청 성공은 해당 테스트 범위의 읽기·삽입·수정 가능성을 확인하며 계정 전체 권한/요금제를 API로 증명한 것은 아니다.
