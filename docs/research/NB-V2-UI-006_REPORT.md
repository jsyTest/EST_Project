### 비밀번호 아이콘

기존 버튼은 display:grid였고 ::before 아이콘과 font-size:0인 실제 버튼 텍스트가 각각 Grid 항목으로 참여했다. 실제 Chrome에서 행 크기 32px/12px, 아이콘 중심이 입력창 중심보다 6px 높은 것을 재현했다.

버튼 내부를 Flex 중앙 정렬로 바꿔 두 행 구조를 제거했다. 표시 상태의 ::after 대각선은 top/left 50%와 translate(-50%,-50%)로 중앙을 지정했다. 원래 버튼 텍스트·표시/숨기기 이벤트·aria-label·aria-pressed는 변경하지 않았다.

Chrome DOM.getBoxModel로 아이콘 ::before의 실제 경계 중심을 측정했다. 네 해상도의 로그인·회원가입·빈값 오류 모두 수직 오차 **-6px → 0px**다. 버튼은 44×44, 입력은 50px 높이를 유지한다. 실제 클릭으로 password↔text, aria-pressed와 ‘표시/숨기기’ 레이블 전환도 확인했다. 비밀번호나 실제 계정 값은 입력하지 않았다.

### 폼 간격

공통 form gap만 12px에서 8px로 줄였다. 이메일 입력 하단→비밀번호 레이블 상단의 실제 간격은 네 해상도에서 **35px → 31px**다. 빈 오류 슬롯의 min-height:18px와 여백은 그대로다.

수정 후 각 해상도의 로그인/회원가입 정상 빈 폼과 빈값 오류 폼의 카드 x/y/너비/높이가 동일함을 확인했다. 카드 너비·뷰포트 중심 정렬·로고/PPLUS 크기·CTA 너비/높이도 전후 동일하다. 간격 축소로 카드 자체는 로그인 8px·회원가입 12px 낮아졌으며, 중심 정렬은 유지된다. 서버 오류의 긴 문장 등 모든 오류 형태를 시험한 것은 아니다.

## 3. 실제 관리자 버튼 검토

js/auth.js의 initializeAccount는 관리자 링크 → 이메일 → 로그아웃 → 오류 영역 순서로 계정 메뉴를 구성한다. 링크는 처음 hidden이고 publishRole에서 서버가 확인한 authorized일 때만 표시한다. js/admin-access.js는 /api/admin/overview 응답의 사용자 ID·admin 역할을 확인한다.

관련 JS와 공통 헤더/계정 CSS는 수정하지 않았다. 기존 시연에는 실제 계정 영역이 없어 관리자 버튼·긴 실제 이메일·로그아웃의 시각 위치는 여전히 미검증이다. 인증 우회·실계정 세션 접근·테스트 계정 생성은 하지 않았다. 사용자 본인의 정상 로그인 화면 확인이 추가로 필요하다.
