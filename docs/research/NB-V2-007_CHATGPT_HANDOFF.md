| 방식 | 가능한 자동화 | 남는 확인과 실제 진단 |

| 함께 | 폼의 유형·선택지와 CSV 실제 컬럼 연결 | 서로 다른 버전/중복/불일치. 동일 예제는 검토 0·오류 0. 두 자료를 강제할 이유는 없음 |

권고 흐름은 **하나 입력 → 분석 → 예외만 확인 → 생성 대상/DB 요약 확인 → 생성·재조회 → 결과 링크**입니다. 로그인·연결·파일 선택·회사 복제를 제외한 제품 내 기본 2클릭(분석/생성)을 목표로 하되, 현재 실제 생성 경로는 없으므로 이미 2클릭으로 생성된다고 보고하지 않습니다.

## 생성 방식 비교와 중요한 한계

1. **개인 Notion 생성→회사 복제:** 우선 검증 후보입니다. 빈 구조를 한 묶음 내부에 만들고 사용자 손으로 회사에 복제합니다. 회사 연결 없이 시작할 수 있지만 복제 후 관계·계산·원본 참조 독립성은 이번에 실험하지 않았습니다. 다른 계정의 비공개 공유 절차는 바깥 공유 컨테이너와 안쪽 생성 묶음을 구분해야 합니다. [공식 이동·복제](https://www.notion.com/help/transfer-content-to-another-account)
2. **고정 템플릿→CSV:** 반복 구조에는 간단하지만 사용자별 임의 구조와 모듈에 약합니다. CSV 새 가져오기는 관계·롤업·수식을 생성하지 못하며 기존 DB 가져오기와 관계 복구를 구분해야 합니다. [공식 CSV 가져오기](https://www.notion.com/help/import-data-into-notion)
3. **향후 사용자 OAuth:** 사용자가 승인한 공간에 직접 생성·확장할 수 있는 방향입니다. Supabase 로그인과 Notion 권한은 별개입니다. 페이지 범위·서버 인증·비밀 저장·access/refresh token 관리·회사 정책을 처리해야 합니다. 기존 internal token은 다른 사용자의 개인 연결로 사용할 수 없습니다. [공식 OAuth](https://developers.notion.com/guides/get-started/authorization)

복제 실험은 먼저 두 개인 테스트 공간/별도 계정에서 관계 2개 DB·롤업·수식·색상·가상 행으로 수행할 것을 권합니다. 복제본에서 값 변경 시 원본이 바뀌지 않는지, 관계 대상 ID가 복제본인지, 원본 접근 없이 계산되는지 확인해야 합니다. 회사 환경 성공은 회사 검증 전까지 주장하지 않습니다. 공개 템플릿과 비공개 초대는 별도 권한/노출 경로입니다.

**회사로 복제한 뒤의 모듈 추가는 별도 문제입니다.** 개인 원본 토큰은 회사 복제본의 ID/수정 권한을 자동으로 갖지 않습니다. 회사 연결 없이 제공 가능한 범위는 원본 재생성→재복제 또는 수동 변경 안내입니다. 이를 기존 회사 DB에 자동 업데이트된다고 설명하면 안 됩니다.

## 공통 DB와 모듈 권고안

- **최소형:** 신청·참가 기록 DB 1개, 관계 없음. 1행=신청 기록. 행 수를 고유 사람 수라고 부르지 않습니다.

- **확장형:** 참여 등록·회차/출석·팀·개인/팀 제출·심사·성과·설문을 선택적으로 추가합니다. 수료가 단순 판정이면 참여 속성으로 충분하며 별도 DB를 강제하지 않습니다. 익명 만족도에 사람 관계를 강제하지 않습니다.
- 고유 사람/과정별 신청/실제 참여/팀 소속 수를 분리합니다. 이름만으로 합치거나 팀원 수를 단순 합산하지 않습니다. 출석은 대상 회차와 누락 처리, 수료/심사는 분모·기준이 정해져야 계산을 만듭니다.
- registry(module ID/version/dependencies) → 순수 DB 계획 → 기본 DB → 관계 → 계산 의존성 순서 → 실제 재조회 구조를 권고합니다. 원격 ID manifest, job 잠금/중복 방지, 사용자 변경과 기존 데이터 보존이 필요합니다.

옵션 기본 색상은 자동 적용하고 사용자 수정만 override로 남깁니다. 신청 결과는 Select, 예정/진행/완료는 Status가 적합합니다. 현재 공식 API 문서는 Status 옵션 group 지정을 지원하되 그룹 자체의 이름/순서 변경은 Notion에서 관리하도록 설명합니다. API 전체 지원과 이 프로젝트의 실제 생성 검증을 구분해야 합니다. [공식 속성 변경](https://developers.notion.com/reference/update-data-source-properties)
