## 구현한 사용자 흐름

홈과 기존 mapping.html에서 ‘새 Notion DB 구성하기 → 폼 또는 CSV → 분석 요약 → DB 구성 미리보기’를 제공합니다. 기존 V1 목적·관리 모듈·추가 요구사항·결과 화면은 접힌 별도 경로로 보존했습니다.

- 폼 단독: 기존 번호형 질문 파서·선택지·명시적 유형 우선순위 사용.
- CSV 단독: 파일/텍스트 중 선택. 폼 불필요. 헤더만 있는 입력도 지원.
- 폼+CSV: 확실한 동일명/별칭을 연결하고 남은 항목을 보존. 중복/모호한 연결은 필수 확인.
- 일반 교육/해커톤 값을 저장하지만 유형별 새 생성 엔진은 없습니다.
- 고급 설정은 기본 접힘이며 속성명·유형·DB·포함/제외·CSV 연결·옵션·색상·Status 그룹·직접 추가·확인 상태 편집을 유지합니다.
- 기본 저장 버튼은 남기고 저장 패널을 입력 아래로 옮겼습니다. 목록·복사본·새 설계는 접힌 보조 영역에 있습니다.

## 안전한 추천과 집계

폼 질문 수, CSV 컬럼 수, 최종 추천 속성 수, 자동 처리/확인 완료, 필수 확인, 제외, 중복/충돌 표시 수를 구분합니다. 최종 속성 수에는 기본 운영 속성과 자동 제목 속성이 포함되며 컴파일 결과와 일치하는지 검사했습니다.

불명확한 CSV 헤더와 선택지 없는 선택형 별칭은 Text로 진행합니다. 이메일·전화번호는 명확한 유형을 유지합니다. CSV 응답 값이나 임의 선택지는 추정하지 않습니다. Text 권장/불일치는 안내하며 미리보기를 허용하고, 구조 충돌은 차단합니다. 확인 완료 버튼으로 실제 중복 이름 등의 제약을 우회할 수 없습니다.

폼 질문 0개와 CSV 컬럼 0개는 분석 성공으로 처리하지 않습니다. 폼 분석 실패를 CSV 성공으로 숨기지 않습니다. 기존 수동 추가 속성의 확인 후 미리보기 조건은 유지합니다.

## CSV와 데이터 보존

기존 첫 레코드 파서를 공유하여 BOM·한글·인용 쉼표·escaped quote·인용 줄바꿈·UTF-8/EUC-KR 파일 처리를 유지합니다. 첫 레코드는 최대 64 KiB입니다.

CSV 원문/응답 행/파일은 서버나 임시 저장 모델에 넣지 않습니다. 분석 성공 후 텍스트 입력칸도 헤더만 남깁니다. 분석 전 CSV 원문은 복원하지 않습니다. CSV 변경 후 분석하지 않은 채 저장하면 분석 후 저장하라는 안내로 차단하여 이전 헤더를 새로 저장한 것처럼 표시하지 않습니다.

긴 CSV 헤더는 원본을 유지하고 추천 속성명만 100자로 줄입니다. 줄인 이름끼리 충돌하면 필수 확인입니다. 입력 변경 시 기존 미리보기를 무효화하고 비동기 읽기 중 바뀐 입력에 오래된 결과를 적용하지 않습니다.

## 저장 형식·실제 DB 확인

version 1과 기존 매핑/컬럼/옵션/색상 모델을 유지했습니다. requirements.educationType만 선택적으로 허용하고 없는 과거 값은 education으로 읽습니다. 기존 저장 설계를 열 때 강제 재분석하거나 편집값을 덮어쓰지 않습니다.

Supabase의 현재 제약/RLS를 SELECT로 조회했습니다. schema_version=1, JSON version=1·requirements/mapping 객체·524288바이트·제목 1~80자 제약을 확인했습니다. RLS enabled/forced 및 사용자 소유권 SELECT/INSERT/UPDATE 정책, UPDATE의 USING/WITH CHECK를 확인했습니다. 테이블/정책/업무 행/Auth 설정은 변경하지 않았습니다.

로컬 자동 검사와 실제 Chrome의 가상 DB에서 입력·교육 유형·모듈·헤더·매핑·사용자 속성명·옵션 색상 저장/복원, 새 임시 캐시에서 저장 행 열기를 확인했습니다. **실제 Supabase INSERT/UPDATE·두 계정 RLS 재검증 결과는 아닙니다.**
