## 3. 로그인·회원가입 디자인

- 배경 #F8F7FC, 텍스트 #211A36, CTA #6D4CFF, 보조색 #DCD6FF, 상태 강조 #0D9488을 사용한다.
- 흰색 카드 최대 424px, 기본 내부 padding 32px, 모바일 28px/24px, 둥근 모서리 18~20px와 약한 그림자.
- 브랜드 → 로그인/회원가입 제목 → ‘교육 운영을 더 쉽고 체계적으로 관리하세요.’ → 입력 → CTA → 상태 안내 → 전환 링크 순서.
- 로그인·회원가입 모두 같은 카드·타이포그래피·간격을 공유한다. 별도 안내 문단을 추가하지 않았다.
- 모든 인증 입력은 높이 50px, CTA 최소 48px, 표시 버튼·전환 버튼은 44px 터치 영역이다.
- 표시/숨기기는 기존 aria-label·aria-pressed·텍스트 갱신을 그대로 사용한다. CSS로 눈 아이콘을 그리고 눌림 상태를 구분했다. 원래 버튼 텍스트는 DOM에 남는다.
- 포커스·오류·성공·비활성 스타일을 정리했다. 오류 한 줄 영역을 확보하고 긴 메시지는 줄바꿈한다. 여러 줄 오류나 가입 완료 안내는 필요한 만큼 카드 높이를 늘린다.
- 고정 카드 높이나 overflow:hidden으로 내용/스크롤을 자르지 않았다. 화면 높이가 낮거나 회원가입 내용이 길면 auto margin이 0이 되고 페이지가 길어진다.
- 가입 최소 길이·확인·인증 메일·이동·세션 동작은 변경하지 않았다. 기존 로컬 8자 기준과 실제 서버 정책 미확인 상태를 유지한다.

## 4. 헤더·계정 영역

index·mapping·result·admin 모두 site-header-leading과 같은 PPLUS 브랜드 구조를 사용한다. 기존 DB 구성 미리보기·Mock 프로토타입 표시는 보존했다. 관리자 화면에는 상단 ‘서비스로 돌아가기’를 쉽게 찾을 수 있도록 배치했다.

데스크톱 오른쪽은 관리자 보조 링크 → 이메일 → 로그아웃 순서다. 관리자 링크는 작은 흰색/중립 테두리 버튼으로 CTA보다 약하게 표시한다. 동적 DOM도 같은 순서여서 시각·키보드 순서가 일치한다.

680px 이하에서는 브랜드 줄과 계정 메뉴 줄을 분리한다. 관리자 버튼·줄임표 이메일·로그아웃을 같은 계정 영역 grid에 넣어 가로 폭을 제한했다. 일반 사용자/권한 확인 중에는 숨겨진 관리자 칸을 없애고 이메일·로그아웃만 배치한다. 별도 드롭다운이나 새로운 권한 로직은 추가하지 않았다. 전체 이메일은 DOM 텍스트에 유지한다.

js/auth.js 변경은 안내 문구·계정 그룹 접근성 레이블·표시 순서·클래스뿐이다. 서버 역할 확인, hidden 변경 조건, 로그인·가입 요청, 로그아웃 콜백, 세션·계정 변경 처리는 유지했다.

변경 전 서버는 시작 HEAD의 공개 파일을 임시 디렉터리로 복사해 제공하므로 작업 트리를 되돌리지 않았다. 시연은 기존 기능이며 가상 계정·수치라는 배너가 있고 운영 빌드에서 제외된다. 실제 관리자·운영 데이터 검사로 취급하지 않는다. 실제 계정 헤더는 로그인 후 확인해야 한다. 로그인은 사용자 본인이 직접 진행하고 비밀번호·토큰을 대화에 보내지 않는다. 이번 새 가입·인증 메일 검사는 수행하지 않았다.

두 서버는 127.0.0.1에만 열었고 임시 실행 파일은 프로젝트 밖에 뒀다. 공개 설정만 프로세스 안에서 사용해 기존 서버의 읽기 인증 경로를 준비했으며 원격 읽기 성공을 새로 검증한 것은 아니다.

배포 전 확인: 위 네 해상도에서 카드 위치·짧은 화면 세로 스크롤·오류 줄바꿈·비밀번호 아이콘·키보드 포커스·계정 메뉴·표 영역 스크롤·관리자 4개 메뉴를 확인하고 디자인 기대에 맞는지 평가해야 한다. 특히 실제 모바일 키보드·브라우저 줌·긴 이메일은 미검증이다.
