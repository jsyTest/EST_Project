18개 응답의 Cache-Control은 모두 `public, max-age=0, must-revalidate`였다. 기본 GET의 x-vercel-cache는 MISS, 후속 요청은 HIT였다. 200 응답의 Age는 0이며 ETag/Last-Modified도 확인했다. Vary와 CDN-Cache-Control은 이 측정에서 반환되지 않았다. Vercel-CDN-Cache-Control이 보이지 않는다는 이유로 내부 설정도 없다고 단정하지 않는다. 304는 본문 없는 조건부 응답으로 처리해 본문 해시 비교 대상에서 제외했다.

HTTP no-cache 요청은 사용자 브라우저의 강력 새로고침과 동일한 실험이 아니다. x-vercel-cache HIT나 304만으로 구 UI 배포를 증명할 수 없다. 이번에 받은 본문은 모두 최신 로컬과 일치했다.

Cache-Control 및 CDN 응답 헤더의 해석은 공식 자료도 대조했다. 브라우저 재검증과 CDN 응답 상태를 구분한다: [Cache-Control](https://vercel.com/docs/caching/cache-control-headers), [Response headers](https://vercel.com/docs/headers/response-headers).
