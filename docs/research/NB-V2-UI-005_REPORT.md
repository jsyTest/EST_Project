## 1. 결과와 범위

새 JPEG 심볼과 PPLUS 브랜드명을 로그인/회원가입·일반 서비스·관리자 헤더에서 한 그룹으로 복원했다. **로컬 코드 정리·자동/정적/로컬 HTTP 검사 완료, 실제 화면 시각 검토·사용자 피드백 미완료, 미배포**다. UI 디자인 완성이나 운영 반영을 선언하지 않는다.

시작·종료 Git: main / `a4a71fe6e17c3ef9f558c3e6a98243a124ae63c2` (변경 구현 17). 시작 status는 clean이었다. 의도한 디자인 변경은 기존 파일 6개, 새 문서는 2개다. 작업 중 의도한 수정 범위 밖의 `.DS_Store`, `assets/.DS_Store` 변경도 관측됐으며 원인을 단정하지 않고 그대로 보존했다. reset·clean·checkout·commit·push는 하지 않았다.

## 2. 실제 DOM 조사와 변경

UI-004 기준 5개 HTML의 pplus-brand에는 심볼 JPEG만 있고 별도 PPLUS 문자가 없었다. 각 그룹에 pplus-wordmark span 1개를 추가했다. 로그인/회원가입은 동일 login.html을 공유하므로 같은 그룹·스타일이다.

- login.html: 카드 상단 중앙에 심볼 + PPLUS, 아래에 기존 로그인/회원가입 제목과 안내 1문단 유지.
- index.html·mapping.html·result.html: 기존 헤더 왼쪽 브랜드 링크 안에 심볼 + PPLUS.
- admin.html: 같은 헤더 그룹을 사용하고 기존 서비스 복귀 링크 보존.
- css/auth.css: 심볼과 브랜드명 간격·워드마크 타이포그래피만 추가/조정.

기존 제목·안내 중복을 만들지 않았고 ‘AI 노션 빌더’ 문구를 되살리지 않았다. 헤더 오른쪽 관리자 버튼·이메일·로그아웃 구조와 크기는 그대로다. 모바일은 UI-003의 브랜드 줄/계정 줄 분리 grid를 유지한다. 관리자 링크는 기존 서버 확인 전 hidden 상태를 유지하며 새 판정 로직은 없다.

## 3. 표시 크기·여백과 접근성

| 위치 | 심볼 이미지 / 받침 | PPLUS 글자 | 심볼↔문자 | 그룹 아래 여백 |
| --- | --- | --- | --- | --- |
| 로그인/가입, 480px 초과 | 64×64 / 64×64 | 28px, 800 | 14px | 20px |
| 로그인/가입, 480px 이하 | 56×56 / 56×56 | 26px, 800 | 12px | 16px |
| 일반/관리자 헤더, 680px 초과 | 36×36 / 44×44 | 20px, 800 | 10px | 기존 헤더 구조 유지 |
| 일반/관리자 헤더, 680px 이하 | 32×32 / 40×40 | 20px, 800 | 10px | 기존 계정 줄 유지 |

브랜드 그룹은 align-items:center이며 카드에서는 justify-content:center다. 글자는 line-height:1·nowrap으로 표시한다. 기존 카드 최대 424px·모바일 padding·auto margin 중앙 배치·짧은 화면 스크롤 동작은 변경하지 않았다. 위 값은 CSS 값이며 브라우저 실측이 아니다.

보이는 PPLUS 문자가 접근 가능한 브랜드 이름을 제공하므로 심볼은 alt 빈값·받침 aria-hidden=true로 처리해 중복 낭독을 피했다. 원본 width/height=314와 decoding=async를 유지했다. 링크의 href·aria-label은 변경하지 않았다. 이미지 실패 시에도 보이는 PPLUS 문자는 남지만 실제 실패 화면의 시각 품질은 미검증이다.

## 4. JPEG 원본·품질

원본 `assets/logo_1.jpeg`의 314×314 비율·픽셀·압축·흰 배경을 유지했다. SHA-256은 시작·종료 모두 `c1f8a47e16a950e0aa55b5ded53818b576a14585f6e940006716ac07dd867d98`이다. PNG 변환·배경 제거·재생성·재압축·업스케일은 하지 않았다.

## 7. 실행 중인 로컬 주소와 검토 순서

기존 로컬 서버 PID의 127.0.0.1:8795 LISTEN 상태와 HTTP 응답을 확인했다. 해당 서버가 새로 빌드된 UI-005 파일을 제공하며 브라우저/스크린샷 피드백을 받을 수 있도록 실행 상태로 유지했다.

- 로그인: http://127.0.0.1:8795/login.html
- 회원가입 화면: http://127.0.0.1:8795/login.html?mode=signup
- 교육 설계/헤더: http://127.0.0.1:8795/index.html
- 매핑/헤더: http://127.0.0.1:8795/mapping.html
- 결과/헤더: http://127.0.0.1:8795/result.html
- 실제 관리자: http://127.0.0.1:8795/admin.html
- 기존 가상 UI 시연: http://127.0.0.1:8795/__demo/admin.html

보호된 화면은 본인 계정 로그인이 필요하다. 가상 시연은 예시 배너와 가상 데이터를 사용하는 기존 로컬 도구로 실제 권한·회원 데이터 검증이 아니며 공개 빌드에서 제외된다. 관리자 화면에서 대시보드→회원 관리→이용 현황→설정을 각각 선택해 확인할 수 있다. 계정·통계가 연결되지 않은 실제 운영 영역은 계속 ‘추후 연결 예정’으로 남아 있다.

사용자 검토: 네 해상도에서 로그인/가입과 헤더, 관리자 4개 메뉴를 캡처해 브랜드 중심선·간격을 확인한다. 이메일 공란/잘못된 형식·빈 비밀번호의 로컬 검증 오류로 안내 줄바꿈을 확인하고, 화면 준비/처리 중 로딩 모습은 실제 브라우저에서 별도로 확인한다. 실제 회원가입·설계 저장·계정 변경을 임의로 수행하지 않았다. 비밀번호·JWT·쿠키는 대화에 보내지 않는다.

스크린샷 피드백이 제공되면 해당 화면·해상도와 현재 로컬 파일을 기준으로 조정할 수 있는 상태다. 현재 사용자 시각 피드백을 받거나 반영한 것은 아니다.
