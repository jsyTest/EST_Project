## 2. 원인과 최종 헤더

관리자 버튼은 정적 HTML이 아니라 js/auth.js가 동적으로 생성했습니다. 공통 함수가 관리자 페이지에도 같은 버튼을 붙여 자기 링크가 생겼습니다.

일반 서비스 index·mapping·result:

- 왼쪽: JPEG 심볼 + PPLUS + 기존 화면 표시.
- 오른쪽: 서버 권한 확인 후 관리자 페이지 → 이메일 → 로그아웃.
- 세 화면 HTML은 그대로이며 일반 사용자의 버튼 숨김도 유지합니다.

관리자 페이지:

- 왼쪽: JPEG 심볼 + PPLUS.
- 오른쪽: 서비스로 돌아가기(`/index.html`) → 이메일 → 로그아웃.
- admin.html에 복귀 버튼이 있는 정적 계정 슬롯을 두고 공통 JS가 이를 재사용합니다.
- 관리자 페이지에서는 관리자 자기 링크를 생성하지 않습니다.
- 브랜드 링크의 기존 주소·접근성 이름은 보존했습니다.

## 3. 제거한 중복과 유지한 기능

브랜드 옆 복귀 텍스트·사이드바 복귀 링크·관리자 자기 링크를 제거했습니다. 명시적인 복귀 버튼을 헤더 하나로 통합하기 위해 권한 안내·설정의 복귀 링크도 제거했습니다. 브랜드 클릭 이동은 유지하며 설정의 기존 로그아웃 액션도 유지합니다.

사이드바에는 대시보드·회원 관리·이용 현황·설정 네 버튼만 남습니다. 메뉴 전환과 설정 로그아웃 이벤트는 그대로입니다. 로그인된 사용자는 권한 확인 실패 때도 헤더 복귀 경로를 쓸 수 있지만 관리자 본문은 차단됩니다.
