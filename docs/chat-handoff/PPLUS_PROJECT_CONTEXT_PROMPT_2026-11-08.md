## 2. 서비스의 목적과 현재 방향

PPLUS는 교육·해커톤 운영 담당자가 폼 문항이나 CSV 컬럼을 바탕으로 Notion DB 구조를 설계하고, 향후 본인이 승인한 Notion 공간에 자동 생성하도록 돕는 서비스입니다.

현재는 **AI API를 사용하지 않는 규칙 기반 서비스**입니다. 초기 V1 Mock 설계안과 구조화된 DB 생성 계획을 구분해야 합니다. 저장된 설정에서 계획을 계산할 수 있지만, 웹사이트에서 실제 Notion DB를 생성하는 기능은 아직 연결되지 않았습니다.

지향하는 흐름:

    로그인 → 교육·해커톤 설정 입력 → 네이버 폼·CSV 분석
    → 속성·유형·옵션·색상 확인 → DB 구성·모듈 선택
    → 내 설계 저장 → 서버에서 저장본 검토·Notion 계획 미리보기
    → 향후 본인 Notion 연결·대상 확인·최종 승인 → 생성·결과 확인

초기 PROJECT_SPEC.md에는 ‘AI 노션 빌더’, ‘AI 설계 생성’ 등 과거 기획 표현이 남아 있습니다. 그 문서만으로 현재 AI 기능이 있다고 해석하거나 최신 규칙 기반 방향을 되돌리지 마세요.

## 5. Supabase에 저장하는 것과 Notion에 만드는 것

기존 업무 테이블은 `public.education_drafts`입니다. 새 중복 테이블이나 SQL 없이 현재 설계 저장 기능을 유지할 수 있습니다.

주요 구조:

- `id`: UUID 기본키.
- `user_id`: auth.users와 연결된 소유자. DB 기본값 auth.uid().
- `title`: 설계 이름.
- `configuration`: JSONB. requirements, mapping, planner 등 사용자 설정.
- `schema_version`, `created_at`, `updated_at`.
- `configuration.version = 1`, `schema_version = 1`, JSON 크기 제한 512 KiB 유지.
- 저장본에 planner가 없는 과거 version 1은 안전한 기본값으로 읽습니다. 거대한 Dry Run 전체 결과나 Notion 요청 템플릿은 중복 저장하지 않습니다.

기존 적용 기록상 RLS ENABLE/FORCE, 본인 SELECT/INSERT/UPDATE 정책이 있으며 UPDATE는 USING과 WITH CHECK를 모두 적용합니다. 소유자 변경과 임의 ID·시각 지정·DELETE는 클라이언트 허용 범위가 아닙니다.

저장 대상은 **설계 설정**입니다. 실제 교육생 이름·연락처·응답 행·CSV 파일·비밀번호·JWT·Notion 토큰·미구현 KPI 편집값은 저장 대상이 아닙니다. 자유 텍스트의 개인정보를 자동 탐지·제거하는 기능이 있다고 가정하지 마세요.

Notion의 실제 교육 운영 DB·행·관계·계산은 별도 생성 대상입니다. Supabase에 설계를 저장했다고 Notion에 DB가 생긴 것은 아닙니다.

## 6. DB 생성 계획과 실제 Notion 검증 범위

현재 Planner는 `planVersion = 1`입니다.

- 기본형: 신청·참가 구조 1DB.
- 일반형: 사람·프로그램·신청기록 3DB와 관계·Rollup·Formula 계획.
- 확장형: 선택 모듈과 의존 모듈의 DB·관계·계산 계획.
- **현재 일반형 3DB는 교육생·출석·일정 3DB가 아닙니다.** 모집 신청자 분석과 선정 교육생 운영 KPI를 섞지 마세요.
- 교육생·출석·일정 중심 운영 모듈, 사용자 정의 KPI, 자동 대시보드 완성은 후속 목표와 지원 범위를 따로 판단해야 합니다.

실제 Notion 작업 이력:

1. 002/002A PoC: 개인 테스트 공간에서 DB·관계·수식·KPI와 계획별 제한을 검토한 이력이 있습니다. 최종 서비스 전체의 성공 증거가 아닙니다.
2. 009A: 별도 승인 후 개인 테스트 부모 아래 기본형 빈 DB 1개·속성 7개를 실제 생성하고 유형·옵션·색상·빈 상태를 재조회했습니다. 실제 API 검사 34개 통과 기록입니다.
3. 009B: 별도 승인 후 사람·프로그램·신청기록 3DB, 관계 2쌍·Rollup 2개·Formula 2개·가상 행 7개를 생성했습니다. 실제 API 검사 79개 통과와 읽기 전용 재검증 기록입니다. 선정률은 원격 건수를 이용한 로컬 계산이며 Notion 비율 속성 구현으로 확대하지 않습니다.
4. 기본형·일반형 CLI는 계획/대상 해시·manifest·잠금·단계 기록·읽기 재확인을 사용합니다. 불확실한 생성 응답 뒤 무조건 재POST하거나 자동 삭제하지 않습니다.

특히 일반형의 실제 성공은 고정 가상 자료를 이용한 검증입니다. 임의의 모든 저장 설계·확장형·대량 자료·웹 생성이 검증됐다는 뜻은 아닙니다.

회사 Workspace로 복제하거나 직접 생성하는 경로는 실제 성공이 확인되지 않았습니다. 개인 생성 후 회사 복제 성공을 보장하지 마세요.

## 7. 서버 Dry Run과 웹 미리보기

주요 API:

- `POST /api/drafts/review`: 서버 인증·저장 설계 소유권 확인과 계획 검토.
- `POST /api/notion/plans/review`: 저장 설계의 Notion 생성 계획 변환·지원 범위 미리보기.
- `GET /api/admin/overview`: 기존 서버 관리자 확인 경로.
- 개인 테스트 연결 API 두 개는 구현돼 있지만 실제 Notion 원격 실행이 기본 차단돼 있습니다.

서버는 클라이언트가 주장하는 configuration/user_id를 실행 근거로 삼지 않고 저장본을 읽습니다. 없는 설계와 타인 설계는 같은 안전한 404로 처리합니다. 최신 저장 시각·계획 해시가 다르면 409로 거절합니다.

planHash와 compilationHash는 서로 역할이 다르며 **해시는 생성 승인 토큰이 아닙니다.**

012의 웹 미리보기는 DB·Data Source·속성·옵션 색상·관계·Rollup·Formula·구축 순서와 미지원/차단 항목을 보여줍니다. 실제 생성 버튼은 연결하지 않았습니다.

    webExecutionReady: false
    notionExecution: "not_executed"
    notionRequests: 0

실제 본인 계정 확장형 저장본에서 DB 6개·속성 36개·관계 8쌍·Rollup 2개·Formula 3개와 반복 해시 일치를 관찰한 기록이 있습니다. 이를 실제 Notion 생성 결과로 취급하지 마세요.
