보존됐습니다. 로컬 HEAD·실시간 원격 main·현재 운영 배포 SHA가 모두 `7671e47...`입니다. 시작 작업 트리는 clean이었습니다.

UI-001의 로그인·관리자·서버 API·빌드·테스트·문서 변경 24개 파일이 현재 커밋에 들어 있습니다. 이전에 미커밋이던 구현은 지금 Git 이력에 저장돼 있습니다.

  `3fc73f4341bc7e42d87b3c5680c07eb7f6185efacbd83e7d63538997df77aef6`

## 3. 운영 화면·보안 확인

`/`, `/login.html`, `/login.html?mode=signup`, `/admin.html`, `/index.html`, `/mapping.html`, `/result.html`은 모두 200이고 로컬 파일과 일치했습니다.

- 기본 숨김 관리자 버튼과 서버 역할 확인 스크립트.
- 기존 로그인·설계 저장·planner·매핑 관련 자원.

이는 HTTP·소스 검사이며 실제 화면 배치를 시각 확인한 결과는 아닙니다. admin.html의 200은 정적 틀 제공이며 관리자 인증 성공을 뜻하지 않습니다.

## 4. 자동 테스트와 실제 사용자 검증 구분

이번에 전체 Node 검사를 재실행해 **319/319 통과**, 실패·취소·생략 0을 확인했습니다. **V1 256조합 검사도 이 테스트 안에 포함돼 통과**했습니다.

자동 검사에는 다음이 포함됩니다.

- 이메일 빈값·형식, 비밀번호 빈값·인증 실패 안내.
- 비밀번호 표시/숨기기, 가입 모드·확인 불일치.
- 로그인 이동·세션·로그아웃·계정 전환 관련 기존 흐름.
- 일반 사용자 관리자 버튼 숨김·직접 URL 차단·API 403.
- 서버 확인 후 관리자 허용·본인 정보 표시.
- 늦은 응답·로그아웃·계정 전환 시 관리자 상태 제거.
- 기존 저장·planner·폼·CSV·색상·Notion CLI·공개 빌드 회귀.

위 인증·화면 자동 검사는 모의 Auth·DOM 기반입니다. 정상 실제 계정으로 API 200이나 일반 사용자 403을 새로 확인한 증거는 아닙니다.

CUA의 브라우저 연결은 browser host unavailable로 사용할 수 없었습니다. 사용자는 이번 실계정 검사를 직접 하기 어렵고 일반 계정도 확인하지 못했다고 답했습니다.

**이번 미검증:**

- 현재 Git 운영본의 정상 실계정 로그인→이동→새로고침→로그아웃.
- 실제 관리자 버튼·본인 정보와 실제 일반 사용자 접근 차단.
- 실제 교차 탭·계정 전환.
- 모바일 너비별 입력창·버튼·오류 줄바꿈·겹침·터치 동작.
- 실제 Supabase 비밀번호 정책·새 회원가입·인증 메일.

UI-001 당시 사용자 관리자 성공 확인은 과거 증거로만 남겼습니다. 이번 실사용 성공으로 바꾸어 기록하지 않았습니다. 비밀번호·JWT·쿠키 수집이나 계정 생성은 하지 않았습니다.
